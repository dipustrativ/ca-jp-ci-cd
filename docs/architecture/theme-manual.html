Carpient Theme Manual

Theme carpient/rugs — layout, build commands, and the 404 page.

1. Theme

  • src/app/design/frontend/carpient/rugs/, parent Magento/blank.
  • Set at default scope only, so it applies to all 12 store views across all three websites — base (en, de, es, fr, it, hu, nl, pl, pt, fi), ca_dk (dk) and ca_se (se).
  • carpetavenue/rugs is a leftover DB row from an older sibling theme. It has no files on disk and is assigned nowhere. Do not confuse the two.

<Module_Name>/templates/*.phtml     template overrides

2. Build & cache

# after LESS / JS changes
docker exec carpient-phpfpm-1 sh -c "cd /var/www/html && \
  php bin/magento setup:static-content:deploy -f --area frontend --theme carpient/rugs en_US"

# LESS watch loop with source maps
docker exec -it carpient-phpfpm-1 sh -c "cd /var/www/html && npx grunt watch:rugs"

.phtml and layout XML need no deploy, only a cache clear. PHP classes need docker restart carpient-phpfpm-1 carpient-phpfpm-xdebug-1 (opcache).

Two dev-stack traps. carpient-redis-1 is not on the carpient_default network, so Magento degrades to a file cache and bin/magento cache:flush clears nothing — use rm -rf var/cache/* var/page_cache/* inside the container. And static-content:deploy -f skips CSS whose file is newer than the source; delete pub/static/frontend/carpient/rugs/<locale>/css first to force a recompile.

3. 404 page

3.1 Files and records

WhereWhat
Magento_Cms/layout/cms_noroute_index.xml 1 column, drops page title + breadcrumbs, adds the template and the content slot.
Magento_Cms/layout/cms_index_defaultnoroute.xml One <update> pulling in the handle above, for the fallback case.
Magento_Cms/templates/notfound.phtml Markup: 404, heading, sentence, button. Strings go through __().
web/css/source/_extend.less .carpient-notfound styles, end of file.
i18n/<locale>.csvThree translated rows per locale.
CMS page no-route One page, All Store Views, Content empty. Supplies the browser-tab title only.
CMS block notfound_bottom Optional admin content below the message — currently a Catalog Products List widget.

Handle name. A normal 404 renders cms_noroute_index (cms/noroute/index). cms_index_defaultnoroute is the fallback action Magento forwards to only when the no-route CMS page is missing, disabled, or not assigned to the current store view — that is the page printing "There was no 404 CMS page configured or found." A layout file placed only under that second name never loads on a normal 404.

Keep the cms_page block. It sets <title> from the CMS page; removing it renders an empty title tag. Harmless to keep, since the page's Content is empty.

3.2 Changing the text

English is in the template; other languages in i18n/<locale>.csv:

"Page not found","Seite nicht gefunden"
"Sorry, the page you requested does not exist.","Die angeforderte Seite existiert nicht."
"Back to home","Zurück zur Startseite"

Translations need Locale set at store-view scope (general/locale/code); all eleven store views are set. Without it a store view falls back to en_US and shows English.

The tab title comes from the CMS page and is 404 Not Found in every language. To translate it, swap the single page for one page per store view — same identifier no-route, each assigned to one store view, each with its own title. Nothing else changes.

3.4 Content slot below the message

<block class="Magento\Cms\Block\Block" name="carpient.notfound.bottom" after="carpient.notfound">
    <arguments><argument name="block_id" xsi:type="string">notfound_bottom</argument></arguments>
</block>

Missing or disabled block renders nothing. It currently holds a heading and a Catalog Products List widget matching all products, added in the admin with Insert Widget. Placeholder for testing — decide before go-live what production shows. The block is All Store Views, so its heading is English everywhere; one block per store view translates it.

3.5 Production rollout

  1. Deploy the theme files, run a static-content deploy, clear the cache.
  2. Set Locale per store view if not already set.
  3. Create the CMS page: URL Key no-route, Content empty, Layout 1 column, All Store Views.
  4. Optionally create the notfound_bottom block.
  5. Verify a nonsense URL per store view returns HTTP 404 with that language's copy.

Leave the CMS No Route Page config on its system value.

3.6 Known

  • Store-view locales affect the whole storefront, not just this page: all translations plus date and number formatting.

4. Language switcher

Expected behaviour when switching store view:

  • Product, category, CMS page → the same entity on the target store view, using its own URL key (/it/tappeti-…-epr1006 → /en/oriental-carpets-…-epr1006). Core Magento\UrlRewrite\Model\StoreSwitcher\RewriteUrl does the mapping.
  • 404 → the target store view's home page, since the requested path exists nowhere.
WhereWhat
Magento_Theme/layout/default.xml Container carpient.nav.utils in store.menu, after catalog.topnav; holds About us, currency and store_language.
Evalent_MegaMenu/templates/html/topmenu.phtml Renders the menu and the "Contact us" pill only — no utility row.
Carpient\Theme\ViewModel\HomeSwitcherUrlProvider Switcher links that point at the target store view's home page.
Magento_Cms/layout/cms_noroute_index.xml Swaps that view model onto store_language / store.settings.language.

Never put the switcher inside catalog.topnav. That block is cached in block_html for an hour with a store-scoped key (ttl="3600" in Magento_Theme's default.xml, and Topmenu::getCacheLifetime() hardcodes the hour, so layout XML cannot switch it off). Switcher links carry a uenc of the current page, so a switcher inside that block serves one page's links on every page of the store view — whichever page warmed the cache. That was a live bug: every page offered to switch to some unrelated URL.

Adding the request URI to the block's cache key also fixes it, but the entry is ~214 KB, so the cache would then hold one copy per URL per store view instead of one per store view. Keeping the utility row outside the cached block costs nothing and was the fix taken. The desktop CSS keys off .carpient-nav-utils with no ancestor selector, so the row renders identically as the next sibling of <nav>.
